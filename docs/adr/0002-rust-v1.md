# ADR-0002: Sergeant V1 is Rust

## Status

Accepted. Supersedes an earlier in-flight prototype of this same ticket
written in TypeScript/Node, which was discarded before anything was
committed once this decision was made.

## Context

The authoritative design doc's "V1 runtime architecture decisions" section
specifies a single long-lived daemon (Tokio async runtime, SQLite,
NanoID-style opaque IDs, systemd process supervision, one dedicated Linux
VM, one `sergeant serve` binary with all responsibilities as modules/tasks
rather than separate services), and explicitly states this supersedes
earlier suggestions to use Node.js/Postgres for V1.

## Decision

Sergeant V1 is implemented in Rust. `sergeant-core` (this ticket's deliverable)
is a plain library crate with no async runtime dependency of its own —
Tokio is a V1-daemon concern, not a domain-model concern, and pulling it
into `sergeant-core` now would add nothing while this crate has no I/O to
overlap. The `sergeant serve` binary that hosts Tokio, the HTTP surface, and
the supervisor/scheduler/reconciliation loops was deliberately **not**
built in this ticket (see the walking-skeleton scope note in `AGENTS.md`
for what was deferred at the time) — it landed in UNF-204.

IDs use the `nanoid` crate with an explicit type prefix (see
`docs/adr/0003-sqlite.md` for the storage side of this), not sequential
integers, per the design doc's requirement that Sergeant-native IDs be
opaque.

## Consequences

- Every later Sergeant ticket that adds runtime behavior (worker
  interface/local runner, provider adapters, HTTP/webhook ingress, CI/job
  watchers) is Rust, building on `sergeant-core`.
- `sergeant-core`'s public API is synchronous (it wraps `rusqlite`, which is
  synchronous); the daemon crate is expected to call it from a
  `spawn_blocking`-style boundary rather than making the domain layer
  async. This keeps `sergeant-core` trivially unit-testable without a runtime.
- systemd supervision, the dedicated Linux VM, and AWS instance roles are
  deployment concerns for the `sergeant serve` ticket, not this one.
